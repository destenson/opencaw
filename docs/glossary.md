# Glossary

Canonical definitions for terms used across OpenCAW. Definitions follow how the term is actually used in this codebase and the design docs — where a term has a general ML meaning, the entry describes the OpenCAW-specific sense. Cross-references point to the authoritative source: [design](design.md), [architecture](architecture.md), [DECISIONS](DECISIONS.md), [storage](storage.md), [benchmarking](benchmarking.md).

---

## Core thesis

**Context as Workspace (CAW)** — The founding thesis: an LLM's context is a *workspace*, not a *container*. Effective capability is set by working-set quality, not total accessible information. The project name (Open-CAW) is this idea. See [design §2](design.md).

**Workspace / working set** — The fragments currently materialized in the model's active context at a given reasoning step, as opposed to everything indexed and *recallable*. Curation is the management of what is in the workspace; recall is what brings things into it.

**Stub-and-recall** — The central architecture: documents are indexed as lightweight **stubs**; full content is **recalled** inline on demand as the model reasons. Trades storage for attention to multiply effective context at roughly flat compute. See [design §3](design.md).

**Recall (vs. retrieval)** — In OpenCAW, *recall* is content materializing inline *during* reasoning, driven by the model's own thinking, with precise provenance — distinct from *retrieval*, a step that runs *before* inference and prepends results. "Recall over retrieval" is a design principle ([architecture](architecture.md)). The differentiator is **thinking-trace-as-retrieval-signal**.

## Indexing and stubs

**Stub** — A lightweight stand-in for a document (or chunk), carrying enough metadata to triage without reading the body: stable id, path, token estimate, mtime, content hash, kind, a short **summary**, and an **outline**. `Stub` lives in `caw-core`. See [design §3.1](design.md).

**StubId** — Stable handle for a stub (`caw-core::StubId`). For file corpora it encodes the source path; the spike's memory corpus uses the relative record path.

**Prompt transformer** — The preprocessor (`caw-transform`) that walks an input prompt, finds file references, and replaces each with a stub, preserving the original span so content can be spliced back. See [design §3.1](design.md).

**Summary** — 1–3 sentence stub description. For prose: LLM-generated by a cheap model. For code: deterministic tree-sitter symbol extraction preferred over summarization. Cached on `(path, mtime, hash)`.

**Outline** — Structural index inside a stub (headings, symbol list, sheet names) for triage without recall.

**Adaptive chunking** — Index granularity decided by file size: small files indexed whole, large files automatically chunked and each chunk indexed independently. No hierarchy. See [design §3.1](design.md).

**Content hash / mtime** — Cache-invalidation keys. Stubs and summaries are keyed on `(path, mtime, hash)`; `get_by_content_hash` lets ingestion skip re-embedding unchanged content.

**Background indexer (with lazy fallback)** — Stub generation runs continuously over workspace files; a file referenced before the indexer reaches it gets stubbed on demand. Amortizes preprocessing for stable corpora.

## Recall mechanisms

**Thinking-trace recall** — Automatic recall for models with visible reasoning: embed each thinking step at step boundaries, match against the stub index, splice hits above threshold. The thinking trace *is* the query. `ThinkingTraceOrchestrator` in `caw-orchestrator`. See [design §3.2](design.md).

**Probe** — An automatic-recall trigger. For visible-trace models, the embedded reasoning step; for hidden-trace models, an explicit `<probe>...</probe>` marker the model emits when reasoning about something it only has a stub for. Matches above threshold inject content. `ProbeRecallOrchestrator`. See [design §3.2](design.md).

**Manual recall (tools)** — Explicit `read_file(id, range)` and `grep(id, pattern)` tool calls for deliberate, precise expansion. Coexists with automatic probes; works with any tool-use model.

**Fragment / RecallFragment** — A unit of recalled content materialized into the workspace: the body plus its `Locator` (provenance), token count, and source mtime. `caw-core::RecallFragment`.

**Locator** — The precise source address of a fragment (`source` + `locator`, e.g. `spec.md` + `4-12`). Drives provenance tagging. `caw-core::Locator`.

**Provenance** — The inline tag on materialized content recording exactly where it came from, e.g. `[recalled from src/auth/middleware.rs:1-62]`. Mitigates **false recall**; lets the model treat content as quoted source and issue precise follow-ups. `ProvenanceFormat` (e.g. `Bracketed`) controls the rendering. See [design §4](design.md).

**False recall** — The failure mode where a wrong stub summary or spurious embedding match makes the model "remember" something untrue of the source, possibly holding a stub-derived prior and conflicting actual content. Precise provenance is the mitigation. See [design §4](design.md).

**LoadMode** — Fragment loading strategy on the `DynamicRecallOrchestrator` (`caw-orchestrator::dynamic`), controlling how/when retrieved fragments are admitted to the workspace.

## Retrieval and embeddings

**Embedding provider** — Pluggable text→vector backend (`caw-index`): FastEmbed, Candle, ONNX, or an API provider. See [embedding providers](embedding-providers.md).

**Asymmetric embeddings** — Using a query/document encoder pair (e5, BGE families): the thinking step is encoded as the *query*, the file as the *document*. See [design §3.4](design.md).

**BGE** — The BAAI general embedding model family; `bge-small` (via Candle) is the default embedder in `caw-server`/spike paths.

**StubStore** — Trait for persisting stubs + embeddings and reconstructing fragment bodies. `get_content` slices `[byte_offset, len)` out of the **source file** — there is no inline-content store. `SqliteStubStore` is the default impl. `caw-core`/`caw-index`. See [storage](storage.md).

**VectorIndex** — In-memory ANN/scan over embeddings. `RetrieverKind::Flat` (brute-force cosine), `Hnsw` (graph via instant-distance), feeding retrieval.

**BM25** — Lexical (keyword) index over `path + summary + body`. Catches exact symbol/term matches the embedding washes out on a single-domain corpus.

**Hybrid retrieval / fusion** — `RetrieverKind::Hybrid`: fuse cosine and BM25 candidate lists, each min-max normalized within its own list, then weighted-summed (`HYBRID_SEMANTIC_WEIGHT` 0.6 / `HYBRID_KEYWORD_WEIGHT` 0.4). A strong lexical match can enter even when the embedding ranked it out. Mirrors `HybridRetriever::balanced`. See [storage](storage.md).

**fetch_k** — Candidate pool size (`max_candidates × 3`) pulled before fusion/clamping, so the lexical half can surface stubs the embedding ranked out.

## Curation

**Curation** — Managing what *isn't* in the workspace. Noise in context is dilutive, not neutral; curation makes the active set sharper. The "other half" of the thesis. `caw-curation`. See [design §8](design.md).

**Curation hooks** — Extension points with overridable default policies: **history summarization**, **history externalization**, **tool output compression**, **system prompt budgeting**, **few-shot management**. See [design §8.1](design.md).

**History summarization** — Compress old conversation turns past a token threshold, preserving decisions/facts/task-state and dropping dead-end reasoning. Most recent K turns kept verbatim (default 3). See [design §8.1](design.md), [DECISIONS](DECISIONS.md).

**History externalization** — Alternative to summarization: write history to the filesystem (one file per session) and recall it via the same stub-and-recall machinery, tagged `[recalled from history/…:turn-N]`. Lossless but retrieval-shaped. See [design §8.1](design.md).

**Session history recall** — Per-turn recall against a separate in-memory vector index of prior turns. Budget-capped at 20% of workspace tokens; does not compete with workspace stubs for slots. Prior model responses compressed to ≤50 tokens before embedding. See [DECISIONS](DECISIONS.md).

**Tool output compression** — Stubbing verbose tool results: full output goes to the index, the context gets a summary stub, recallable on demand. See [design §8.1](design.md).

**System prompt budgeting** — Measuring/capping system-prompt token usage (guidance: under 10% of total budget). See [design §8.1](design.md).

**Overflow strategies** — For tasks needing more simultaneous material than fits: **summary-of-summaries** (recursive, lossy), **multi-pass with reconciliation** (sequential subsets + merge), **surface the constraint** (report what doesn't fit). Default is to surface the constraint. See [design §8.2](design.md).

## Eviction, consolidation, lifecycle

**Eviction** — Removing fragments from the workspace under budget pressure or relevance decay; lowest-relevance first, ties broken by recency. Eviction is **not deletion** — content returns to stub form. See [design §5](design.md).

**Token budget** — Hard ceiling on workspace tokens (`TokenBudget`: `max_total`, `reserved_for_prompt`, `reserved_for_answer`). Never exceeded regardless of relevance.

**Relevance decay** — Each loaded fragment's relevance score decays over reasoning steps; below the unload threshold it becomes an eviction candidate.

**Hysteresis** — Separate load and unload thresholds (defaults: load 0.7, unload 0.4 cosine) to prevent **thrashing** near a single threshold. `RecallThresholds::default_hysteresis`. Starting points pending calibration. See [design §3.4](design.md), [DECISIONS](DECISIONS.md).

**Thrashing** — Rapid load/evict/reload cycling of the same fragment near threshold; what hysteresis prevents and `HysteresisAnalysis` measures.

**Consolidation** — On eviction, the stub absorbs a brief note of what was learned while loaded, so re-recall is informed by the prior visit. Stubs become mutable and richer over time (episodic→semantic transfer). Hybrid: **mid-session annotations** + **eviction-time synthesis**. `ConsolidationSynthesizer` (`MechanicalConsolidation`, `LlmConsolidation` — default). Capped at 2 notes per stub. See [design §5](design.md), [DECISIONS](DECISIONS.md).

**Consolidation note** — The persisted artifact attached to a stub by consolidation (`ConsolidationNote`).

**Mid-session annotation / `<note>`** — Lightweight markers the consuming model emits while reasoning about loaded content, noting what was relevant/concluded. Synthesized into a consolidation note at eviction time.

**Convergence** — Multi-pass recall stop condition: stop when an iteration adds fewer than `convergence_min_new_tokens` (200) or zero new unique stubs. See [DECISIONS](DECISIONS.md).

## Orchestration

**Orchestrator** — The per-turn engine running recall, generation, eviction, and consolidation (`caw-orchestrator`). Variants: **`DynamicRecallOrchestrator`** (the main dynamic loop, `dynamic.rs`), **`ThinkingTraceOrchestrator`**, **`ProbeRecallOrchestrator`**, **`RecallOrchestrator`**. The orchestrator is the differentiator; the `caw-server` proxy does *not* run it.

**run_turn** — The orchestrator's per-turn entry point: initial recall → generate → iterative refinement (thinking-trace/probe/range recall, decay, evict, re-complete) → write session turn → record metrics. See the per-turn flow in [architecture](architecture.md).

**Adapter / ModelAdapter** — Provider abstraction (`caw-adapters`): Anthropic, Groq, Ollama, OpenAI-compat, ClaudeCode, LlamaCpp, **Mock**. `complete()` / optional `generate_passive()`; `capabilities().supports_visible_reasoning` selects the recall path.

**Mock adapter** — A deterministic no-GPU `ModelAdapter` used to prove plumbing and telemetry before wiring a real model.

**Intent classifier / AugmentationSignals** — Classifier output that *changes* retrieval behavior (it is directive, not advisory — see [DECISIONS](DECISIONS.md)).

**Session file** — Append-only per-session record the orchestrator writes each turn and indexes for cross-turn recall (`caw-orchestrator::session`).

## Degradation and operations

**Degradation tiers** — The system degrades per-component in tiers rather than failing atomically: **Full recall** (all healthy) → **Stubs + tools only** (embedding/probe path down; manual tools remain) → **Pass-through** (prompt forwarded unmodified). See [design §6](design.md).

**DegradationMonitor / ComponentHealth** — Per-component health tracking (latency + error rate) selecting the **OperatingTier**; governs `should_auto_recall` / `should_generate_stubs`. `caw-orchestrator::degradation`.

**OperatingTier** — The current effective degradation tier chosen by the monitor.

**ProbeRateLimiter** — Throttles automatic recall when the model emits probes at an excessive rate (thrashing or gaming), falling back to tools-only for that session.

**caw-server** — The OpenAI-compatible drop-in proxy: retrieve → inject → forward. **Single-shot RAG** by design — *no orchestrator, no probes, no multi-pass*. Proves the zero-tool-call UX, not the recall engine.

**Single-shot RAG** — One retrieval pass injected before forwarding, with no reasoning-driven re-recall. What `caw-server` does; contrast with the orchestrator's multi-pass loop.

## Evaluation and benchmarking

**SessionEvaluator** — Records per-turn events (recalls, evictions, probes, annotations, token totals) during a turn and computes metrics. Consumed by `caw-orchestrator` and `caw-bench`. `caw-eval::session`. Attached via `DynamicRecallOrchestrator::with_evaluator`.

**recall@k / precision / grounding** — Core retrieval-quality metrics; recall@k requires a held-out workload with labeled expected ids. See [benchmarking](benchmarking.md).

**Cooperation metrics** — How well a model cooperates with the probe/annotation protocol (`cooperation_metrics`); needs a model that actually emits traces/annotations.

**False-recall metrics** — Quantify spurious recalls via content overlap thresholds (`false_recall_overlap_threshold`).

**Context efficiency** — Ratio of effective workspace content to nominal token cost (`context_efficiency`).

**HysteresisAnalysis** — Diagnostic over load/unload behavior to tune thresholds and detect thrashing.

**NIAH** — Needle-in-a-haystack benchmark workload. Alongside **opencaw** and **sysdoc** Q&A workloads in `caw-bench`. See [benchmarking](benchmarking.md).

**Sweep harness** — Benchmark parameter-sweep tooling for tuning thresholds/budgets. See [benchmarking](benchmarking.md).

## Tokenization / misc

**count_tokens_cl100k** — Token counting via the cl100k (tiktoken) vocabulary (`caw-core`), used for budget accounting.

**Candle / ONNX EP** — Embedding execution backends. Candle is the default GPU path (`bge-small`); ONNX requires the CUDA execution provider with dlopen-by-abs-path for cuDNN. See [embedding providers](embedding-providers.md).

**FADOS** — "Filesystem-as-a-database overlay": a related external tool that builds a queryable index of pointers (path + byte offset + length) back into a source tree, snippets re-read at query time. Conceptual cousin of the stub store. See [design §11 references](design.md).
